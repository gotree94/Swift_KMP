# 6.1 아키텍처 패턴: MVVM, Repository, DI, Clean Architecture

> KMP 앱의 계층을 어떻게 나누고, 테스트 가능하고 유지 보수 가능한 구조를 만들지 학습한다.

---

## 학습 목표

- MVVM 구조를 SwiftUI와 Compose에 각각/공용으로 적용한다.
- Repository 패턴으로 데이터 원천(네트워크/로컬)을 캡슐화한다.
- 의존성 주입(DI)의 기본(수동 주입 → 라이브러리)을 이해한다.
- Clean Architecture의 개념(Domain/Data/Presentation)을 이해한다.

---

## 1. 왜 아키텍처가 필요한가?

규모가 커지면 "화면에서 바로 네트워크 호출 + DB 쓰기 + 비즈니스 조건"이 섞이기 시작합니다.
이를 분리하면:

- 테스트가 쉬워짐 (UI 없이 로직 검증)
- 컴포넌트 교체(예: API 버전 업)가 쉬워짐
- 화면과 비즈니스 로직이 오독 없이 협력

---

## 2. MVVM

```
View (화면)  ──이벤트──▶  ViewModel  ──함수 호출──▶  UseCase/Repository
   ▲                        │
   └───────── 상태(UI State) ◀┘ (StateFlow/@Published)
```

| 계층 | 역할 |
|------|------|
| View | 입력 받기, 상태 렌더링만 |
| ViewModel | UI 상태 정의, 비즈니스 행동 호출 |
| UseCase | 단일 비즈니스 규칙 실행 |
| Repository | 데이터 원천 결정(네트워크/로컬) |

### SwiftUI 예시 (iOS 네이티브)

```swift
// ViewModel
@MainActor
final class TodoListViewModel: ObservableObject {
    @Published var todos: [Todo] = []
    @Published var isLoading = false
    @Published var errorMessage: String?

    private let repository: TodoRepository

    init(repository: TodoRepository) {
        self.repository = repository
    }

    func load() async {
        isLoading = true
        defer { isLoading = false }
        do {
            todos = try await repository.fetchTodos()
        } catch {
            errorMessage = error.localizedDescription
        }
    }
}
```

```swift
// View
struct TodoListView: View {
    @StateObject private var viewModel: TodoListViewModel
    // DI: 초기화 시 전달

    var body: some View {
        List(viewModel.todos) { todo in
            Text(todo.title)
        }
        .task { await viewModel.load() }
    }
}
```

### Compose 예시 (Android 네이티브)

```kotlin
class TodoViewModel(
    private val repo: TodoRepository
) : ViewModel() {

    private val _state = MutableStateFlow<TodoState>(TodoState.Loading)
    val state: StateFlow<TodoState> = _state

    fun load() {
        viewModelScope.launch {
            _state.value = when (val r = repo.fetchTodos()) {
                is NetworkResult.Success -> TodoState.Success(r.data)
                is NetworkResult.Failure -> TodoState.Error(r.message)
            }
        }
    }
}
```

## 3. Repository 패턴

데이터를 어디서 가져올지(서버/DB/캐시)는 Repository가 결정합니다.

```kotlin
interface TodoRepository {
    suspend fun fetchTodos(): List<Todo>
    suspend fun saveTodos(todos: List<Todo>)
}

class TodoRepositoryImpl(
    private val remote: TodoRemoteDataSource,   // Ktor
    private val local: TodoLocalDataSource      // SQLDelight
) : TodoRepository {

    override suspend fun fetchTodos(): List<Todo> {
        // 캐시 우선 → 서버 실패 시 캐시 사용
        return try {
            remote.fetchTodos().also { local.replaceAll(it) }
        } catch (e: Exception) {
            local.loadAll()
        }
    }

    override suspend fun saveTodos(todos: List<Todo>) {
        local.replaceAll(todos)
    }
}
```

- ViewModel은 `TodoRepository` 인터페이스만 알고, 구현체를 모릅니다(의존성 역전에 기여).

## 4. 의존성 주입 (DI)

### 수동 DI (created/main에서 한 번 조립)

```kotlin
// 공용 모듈의 "조립 구성"
class AppContainer(private val platformContext: Any? = null) {
    val httpClient by lazy { createHttpClient() }
    val todoRemote by lazy { TodoRemoteDataSource(httpClient) }
    val todoLocal by lazy { TodoLocalDataSource(databaseDriverFactory()) }
    val repository by lazy { TodoRepositoryImpl(todoRemote, todoLocal) }
}
```

- iOS/Android 진입점에서 `AppContainer()` 하나만 만들어 화면에 전달.
- 테스트에서는 Fake Repository를 수동 주입.

### 라이브러리 DI (KMP)

- **Koin** — Kotlin 멀티플랫폼 DI, 런타임 DI (간단)
- **Ktor DI**(자체) — 필요시
- Android 전용: Hilt(Dagger) — Android 스타일

```kotlin
// Koin 공용 모듈
val appModule = module {
    single<HttpClient> { createHttpClient() }
    single<TodoRemoteDataSource> { TodoRemoteDataSource(get()) }
    single<TodoLocalDataSource> { TodoLocalDataSource(get()) }
    single<TodoRepository> { TodoRepositoryImpl(get(), get()) }
}
```

```kotlin
// Android
startKoin { modules(appModule) }

// iOS
KoinKt.Koin(...)  // 또는 DI 컨테이너를 프레임워크 경계에서 직접 전달
```

> KMP 실무에서 자주 쓰는 조합: **공용 코드는 수동/간단 DI**, 플랫폼 경계는 생성자 주입. 
> Koin은 공용 섹션에서도 가능합니다.

## 5. Clean Architecture (공용 레이어)

```
Presentation (View/ViewModel)  →  Domain (UseCase, 모델, 인터페이스)  →  Data (Repository 구현, Remote/Local)
```

KMP의 공용 모듈 내부 폴더 구성 예:

```
shared/src/commonMain/kotlin/
├── domain/
│   ├── model/Todo.kt
│   ├── repository/TodoRepository.kt (인터페이스)
│   └── usecase/GetTodoUseCase.kt
├── data/
│   ├── remote/TodoRemoteDataSource.kt
│   ├── local/TodoLocalDataSource.kt
│   └── repository/TodoRepositoryImpl.kt
└── presentation/  (Compose 쪽 UI라면 별도 모듈로 분리하는 것이 더 좋음)
```

- Domain은 Kotlin 표준에만 의존(순수 코틀린) → 테스트 용이
- Data는 Ktor, SQLDelight 등 외부 라이브러리 의존
- Presentation은 Compose, SwiftUI, 각 플랫폼 UI

> 전체 UI(Compose)를 공용으로 하면 공용 모듈을 3개(domain, data, presentation)로 쪼갤 수도 있습니다.

## 6. 상태 관리 디자인 (UiState)

### 공용 상태 시 전형

```kotlin
sealed interface TodoUiState {
    data object Loading : TodoUiState
    data class Success(val todos: List<Todo>) : TodoUiState
    data class Error(val message: String, val retry: Boolean = true) : TodoUiState
}
```

- iOS: `TodoUiState`가 Swift에 매핑되어 `switch`로 처리 (Kotlin sealed → Swift enum 제한 있음, `is` 분기로)
- Android: Compose가 sealed class를 그대로

### 단일 이벤트 처리 (SharedFlow)

토스트/스낵바 같은 1회성 이벤트는 StateFlow보다 SharedFlow:

```kotlin
class TodoViewModel(private val repo: TodoRepository) {
    private val _events = MutableSharedFlow<String>(extraBufferCapacity = 1)
    val events: SharedFlow<String> = _events

    fun delete(id: Long) {
        viewModelScope.launch {
            repo.deleteTodo(id)
            _events.emit("삭제 완료")
        }
    }
}
```

## 🛠 실습 2: 테스트 가능한 UseCase (Fake Repository)

**요구사항**

1. `GetTodosUseCase`를 작성
2. 테스트에서 `FakeTodoRepository`(현재 실패/성공 전환 가능) 만듦
3. 성공 시 Success 반환, 실패 시 Error 반환을 commonTest로 검증

```kotlin
class FakeTodoRepository(
    private var shouldFail: Boolean = false
) : TodoRepository {
    var fetchCount = 0

    override suspend fun fetchTodos(): List<Todo> {
        fetchCount++
        if (shouldFail) throw RuntimeException("네트워크 실패")
        return listOf(Todo(1, "테스트", false))
    }

    override suspend fun saveTodos(todos: List<Todo>) {}
}
```
