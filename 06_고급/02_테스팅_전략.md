# 6.2 테스팅 전략

> 공용 로직(commonTest), Android, iOS 각각에서 어떻게 테스트를 작성하고 실행하는지 학습한다.

---

## 학습 목표

- KMP의 테스트 소스셋 구조(commonTest/androidUnitTest/iosTest)를 이해한다.
- 공용 로직을 단위 테스트로 검증한다.
- coroutines 테스트(`kotlinx-coroutines-test`) 사용법을 안다.
- Swift 측 테스트(XCTest)와 Android 테스트(JUnit)를 간단히 연동한다.

---

## 1. 테스트 구조

```
shared/src/
├── commonTest/kotlin/      ← 공용 테스트 (양 플랫폼에서 실행)
├── androidUnitTest/...     ← Android 전용 (JVM)
└── iosTest/...             ← iOS 전용 (Kotlin/Native에서 실행)
```

- `commonTest` 의존성은 보통 `kotlin.test` 사용:

```kotlin
commonTest.dependencies {
    implementation(kotlin("test"))
    implementation("org.jetbrains.kotlinx:kotlinx-coroutines-test:1.10.1")
}
```

## 2. 첫 공용 단위 테스트

```kotlin
// commonTest/kotlin/CalculatorTest.kt
import kotlin.test.*

class CalculatorTest {

    @Test
    fun additionWorks() {
        assertEquals(4, 2 + 2)
    }
}
```

### 테스트 실행

```bash
./gradlew :shared:testDebugUnitTest           # Android/JVM 테스트
./gradlew :shared:iosSimulatorArm64Test       # iOS 테스트
# 또는 전체
./gradlew :shared:allTests
```

> iOS 테스트는 시뮬레이터 런타임을 필요로 할 수 있습니다.

## 3. 검증 어셔선(assertion)과 그룹핑

```kotlin
import kotlin.test.*

class GreetingTest {
    @Test
    fun greetingContainsName() {
        val result = Greeting().greeting("Minho")
        assertTrue(result.contains("Minho"), "이름이 포함되어야 함")
    }

    @Test
    fun standardFunctions() {
        assertEquals("ABC", "abc".uppercase())
        assertNotEquals(1, 2)
        assertNull(null)
        assertNotNull("value")
    }

    @Test
    fun collectionTest() {
        val list = listOf(1, 2, 3)
        assertContentEquals(listOf(2, 4, 6), list.map { it * 2 })
    }
}
```

## 4. coroutines 테스트 (runTest, TestDispatcher)

`kotlinx-coroutines-test`를 쓰면 타이머를 건너뛰면서 빠르게 테스트할 수 있습니다.

```kotlin
// commonTest
import kotlinx.coroutines.test.runTest

class UserRepositoryTest {

    private val repo = UserRepository()  // 실제 네트워크는 피하고 Fake 사용 권장

    @Test
    fun loadsUsers() = runTest {
        val result = repo.fetchUsers()    // suspend 함수
        assertTrue(result.isNotEmpty())
    }
}
```

가상 타이머 제어:

```kotlin
import kotlinx.coroutines.delay
import kotlinx.coroutines.test.runTest
import kotlin.time.Duration.Companion.seconds

@Test
fun delaysAreSkipped() = runTest {
    val start = currentTime
    delay(5.seconds)
    assertEquals(5.seconds.inWholeMilliseconds, currentTime - start)
}
```

> `runTest`는 내부에 가상 클로크를 제공해 실제 5초를 기다리지 않습니다.
> 네트워크/DB가 실제로 붙는 테스트는 통합 테스트로 분리해야 합니다.

## 5. 가짜 구현으로 테스트 (Fake / Mock)

네트워크를 호출하지 않고 강제로 성공/실패를 넣습니다.

```kotlin
class FakeUserApi(
    private val alwaysFail: Boolean = false
) : UserRemoteDataSource {
    override suspend fun fetchUsers(): List<User> {
        if (alwaysFail) throw RuntimeException("서버 오류")
        return listOf(User(1, "테스트유저", "test@example.com"))
    }
}

class UserSyncUseCaseTest {

    @Test
    fun sync_usesCache_onFailure() = runTest {
        val failingApi = FakeUserApi(alwaysFail = true)
        val local = InMemoryLocalDataSource()
        val useCase = SyncUserUseCase(failingApi, local)

        val result = useCase.sync()

        // 실패 시 로컬(빈 리스트) 반환
        assertTrue(result.isEmpty())
    }

    @Test
    fun sync_savesServerData() = runTest {
        val okApi = FakeUserApi()
        val local = InMemoryLocalDataSource()

        SyncUserUseCase(okApi, local).sync()

        assertTrue(local.loadAll().isNotEmpty())
    }
}
```

- 순수 로직 reposity에 대한 테스트는 Fake(가짜)를 최소한으로
- Koin 등 DI를 쓰고 있다면 테스트에서 실제 구현 대신 Fake를 주입해 기준 회귀 테스트 가능

## 6. 상태/Flow 테스트

```kotlin
class TodoViewModelTest {

    @Test
    fun loadingState_thenSuccess() = runTest {
        val vm = TodoViewModel(FakeTodoRepository())

        val states = mutableListOf<TodoUiState>()
        val job = launch { vm.state.toList(states) }

        vm.load()            // 상태 변화 발생
        testScheduler.advanceUntilIdle()

        job.cancel()
        assertTrue(states.last() is TodoUiState.Success)
    }
}
```

## 7. 플랫폼 테스트

### Android (JVM)

```kotlin
// androidUnitTest/kotlin/AndroidSpecificTest.kt
import org.junit.Test
class AndroidSpecificTest {
    @Test
    fun androidRuntimeWorks() {
        assertTrue(true)
    }
}
```

실행:

```bash
./gradlew :shared:testDebugUnitTest
# 또는 결과 리포트
./gradlew :shared:testReleaseUnitTest
```

### iOS (Kotlin/Native)

```kotlin
// iosTest/kotlin/IosSpecificTest.kt
import kotlin.test.*

class IosSpecificTest {
    @Test
    fun iosFoundationWorks() {
        val ns = platform.Foundation.NSString.stringWithString("hello")
        assertEquals("hello".length, ns.length)
    }
}
```

실행:

```bash
./gradlew :shared:iosX64Test              # Intel 시뮬레이터
./gradlew :shared:iosSimulatorArm64Test   # Apple Silicon 시뮬레이터
```

### Swift/XCTest (iosApp)

Xcode에서 iosApp 타겟에 테스트 타깃을 추가하고 XCTest 작성:

```swift
import XCTest
import Shared

final class GreetingTests: XCTestCase {
    func testGreetingContainsName() {
        let greeting = Greeting().greeting(name: "Minho")
        XCTAssertTrue(greeting.contains("Minho"))
    }
}
```

- `Cmd + U`로 iOS 단위 테스트 실행
